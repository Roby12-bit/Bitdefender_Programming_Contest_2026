# Local run

This package contains:

- `statement.pdf` - the problem statement;
- `public_blueprints/` - the directory with the public tests (`north.in`, `south_01.in`, ...,
`south_12.in`);
- `interactor.cpp` - the local interactor;
- `run_local.py` - the script that compiles and runs the solution together with the interactor.

## Requirements

You need:

- Python 3;
- `g++/clang++/c++`, for compiling the interactor;
- the appropriate compiler or runtime for your solution:

| Language | Compiler/Runtime      | Parameters used     |
|----------|-----------------------|---------------------|
| C        | `gcc`/`clang`/`cc`    | `-std=c11 -O2`      |
| C++      | `g++`/`clang++`/`c++` | `-std=c++17 -O2`    |
| Python   | `python3`             | `-u`                |
| Java     | `javac` + `java`      |                     |
| Rust     | `rustc`               | `-O`                |

The script supports solutions written in C, C++, Python, Java, and Rust.

## Basic command

Place your solution in the same directory as the archive files, and run:

```bash
python3 run_local.py
```

By default, the script will run `solution.cpp`. For another file, specify the solution
with `-s` / `--solution`:

```bash
python3 run_local.py --solution solution.c
python3 run_local.py -s solution.py
python3 run_local.py --solution Solution.java
python3 run_local.py -s solution.rs
```

First, the interactor is compiled (from `interactor.cpp`); then the script will compile the solution if it
has been modified, will run it on all tests from `public_blueprints/` and will display the score of each test,
followed by the total score.

After each test, the complete interaction between the solution and the interactor is automatically saved
in a log file in `logs/<solution>__<test>.log`.
The scores of each test and the total score are displayed in the terminal.

## Running on a single test

Use the `-t` / `--test` option to run a single test file:

```bash
python3 run_local.py --test public_blueprints/north.in
python3 run_local.py -t public_blueprints/north.in -s solution.py
```

## Running on a test directory

Use the `--test-dir` option to run all test files from a directory:

```bash
python3 run_local.py --test-dir public_blueprints/
```

## Direct running (without compilation by the script)

If you want to customize the run command, you can provide the command directly after `--`:

```bash
python3 run_local.py --test public_blueprints/north.in -- ./bpc_2026_solution_cpp
python3 run_local.py -t public_blueprints/south01.in -- python3 sol.py
python3 run_local.py -- ./bpc_2026_sol_c
```

Everything following `--` is treated as the run command of the solution.

> **Note:** On Codeforces, only the languages listed above are supported (C, C++, Python, Java,
> Rust), compiled with the parameters specified in the table above.

## Cleaning generated files

To delete the files generated by the script, run:

```bash
python3 run_local.py clean
```

## Observations

- Your program must communicate through `stdin` and `stdout`, according to the protocol in the statement.
- Do not forget to `flush` after each command sent to the interactor if the way you output to `stdout` does not already do this.
